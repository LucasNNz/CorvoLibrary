CORVO LIBRARY V61.9 — FIX11 — MIGRAÇÃO LIMPA DO ACERVO
=========================================================

OBJETIVO
- Retomar produção sem depender do D1 antigo administrativamente inacessível.
- Preservar o acervo real de assets e o mesmo bucket R2.
- Não carregar histórico experimental de filas/leases/execuções/candidatas antigas.

FLUXO
1. Turso é conectado e o login é criado normalmente.
2. Na tela "Restaurar o acervo da Library", selecionar o JSON exportado pela Library antiga.
3. POST /api/migration/catalog-recovery valida e importa o arquivo.
4. A FIX11 cria o schema completo atual (53 tabelas) e os defaults operacionais atuais.
5. Assets são UPSERT por ID, preservando r2_key e todos os metadados úteis.
6. A validação compara total, aprovados, universos, pendentes, rejeitados, reutilizados e usos acumulados.
7. O catálogo é liberado somente após as contagens fecharem.
8. A nova chave R2 pode ser configurada apontando para o mesmo bucket; nenhum objeto é copiado.

DADOS PRESERVADOS POR ASSET
- id
- name
- universe
- kind
- subject
- status / previous_status
- tags
- r2_key
- original_name
- mime_type
- size_bytes
- sha256
- semantic_family
- use_count
- project_origin
- script_reference
- visual_reference
- source_url
- operational_note
- qa_status
- last_used_at / created_at / updated_at

INTENCIONALMENTE NÃO IMPORTADO NESTE MODO
- linhas individuais antigas de asset_usage
- projetos/execuções antigas de teste
- filas
- leases
- decisões antigas do Supervisor
- candidatas/materializações temporárias
- histórico de runtime experimental

SEGURANÇA
- Somente o proprietário autenticado pode chamar a rota.
- O JSON não é gravado no código-fonte nem no R2 pela migração.
- A importação não apaga nem altera o D1 antigo.
- A importação não move, copia ou apaga objetos R2.
- Se o Turso já tiver asset IDs extras fora do JSON, a importação é bloqueada.
- Reexecutar o mesmo arquivo é idempotente (UPSERT pelos IDs originais).
