CORVO LIBRARY V61.5 — FAST PUSH DECISÃO / REJECT / DELETE EM LOTE

OBJETIVO
Reduzir o custo operacional de QA depois de um FAST PUSH grande. A IA, Supervisor ou usuário deve conseguir aprovar/rejeitar dezenas ou centenas de candidatas em uma chamada, sem iterar candidata por candidata.

ROTA PRINCIPAL
1. decidir_candidatas_lote
   - acao: APROVAR | REJEITAR
   - candidate_ids: seleção explícita
   - ou project_id + item_ids/target_files
   - máximo operacional: 200 candidatas por chamada

REGRAS POR PITEM
- REJEITAR por item/PITEM expande para todas as candidatas FAST PUSH ativas daquele item.
- Nunca desfaz PROMOTED_TO_ASSET/FROZEN.
- APROVAR por PITEM só executa quando existe exatamente uma candidata ativa naquele item.
- Com múltiplas opções retorna AMBIGUOUS_REQUIRES_CANDIDATE_ID, exigindo escolha explícita da candidata vencedora.

ALIASES RÁPIDOS
A. aprovar_candidatas_lote
   project_id opcional + candidate_ids + motivo

B. rejeitar_candidatas_lote
   project_id opcional + candidate_ids + motivo

C. rejeitar_itens_lote
   project_id + item_ids e/ou target_files + motivo
   rejeita todas as candidatas ativas desses itens.

HARD DELETE
D. excluir_candidatas_lote
   - project_id obrigatório
   - candidate_ids
   - confirmar=true obrigatório
   - apagar_materializacao opcional
   - apagar_bytes opcional
   - permitir_promovidas=false por padrão

O hard delete remove o envelope FAST PUSH e a candidata canônica de QA. Se a candidata estava em PARA_QA_VISUAL, a fila é reconciliada antes da remoção para que outra candidata do mesmo PITEM possa assumir QA.

SEGURANÇA DE BYTES
apagar_bytes=true só apaga o objeto R2 quando:
- o r2_key pertence fisicamente à própria candidata (fast-push/<candidate_id>/...); e
- não existe referência de outro fast_push_candidate;
- não existe asset permanente apontando para o mesmo objeto;
- não existe materialization_file externo apontando para o mesmo objeto;
- não existe asset de produção/thumb apontando para o mesmo objeto.

Assets permanentes nunca são apagados por excluir_candidatas_lote. Candidatas PROMOTED_TO_ASSET são protegidas por padrão.

API
PATCH /api/fast-push
- mantém compatibilidade com action=approve|reject + candidate_ids
- agora também aceita project_id + item_ids/target_files

DELETE /api/fast-push
- executa o hard delete protegido com confirmação explícita

PRINCÍPIO OPERACIONAL
PUSH MUITO → QA VISUAL → 1 CHAMADA DE DECISÃO EM LOTE → CONTINUAR

O caminho normal é REJECT/APPROVE reversível e auditável. DELETE físico é exceção.
