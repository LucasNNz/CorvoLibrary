======================================================================
1. OBJETIVO
======================================================================

A V60 preserva a V59 e muda o caminho quente do Supervisor para ordens
operacionais compostas:

1 comando do Supervisor
→ SUPERVISOR_PLAN persistido
→ N PLAN_BRANCH
→ ACK rápido
→ workers executam em paralelo
→ fan-in
→ novo work packet apenas em decision boundary.

Antes do fan-out, o source routing aplica filtro duro por domínio, universo,
composition class, capability, configuração e políticas operacionais.

A mesma versão acrescenta o Workspace de Políticas Operacionais para transformar
gaps recorrentes em conhecimento operacional executável, versionado, testável,
mensurável e reversível.

4. WORKSPACE DE POLÍTICAS OPERACIONAIS
======================================================================

Migração 0017 cria:
- operational_gaps
- operational_policies
- operational_policy_events.

O Workspace fica acima de SOURCE_PROFILE e abaixo das CORE_RULES.
SOURCE_PROFILE responde COMO buscar.
Workspace responde QUANDO usar, quando bloquear, fallback, limite e resposta
a falha.

Hierarquia de precedência:
ITEM > PROJECT > PRESET > SEMANTIC_CLASS > COMPOSITION_CLASS > WORK_TYPE >
UNIVERSE > DOMAIN > GLOBAL.

CORE_RULE é imutável e sempre prevalece.
LEARNED_POLICY pode ser DRAFT, TESTING, ACTIVE, PROMOTED, SUSPENDED,
ROLLED_BACK ou DEPRECATED.

======================================================================
5. MEMÓRIA DE GAPS
======================================================================

Gaps recebem assinatura estável e recorrência. Exemplos:
- SOURCE_INCOMPATIBLE|ANIME|POKEAPI
- API_NOT_CONFIGURED|BRAVE
- SEM_FONTES_ATIVAS|NARUTO|ISOLATED
- TIMEOUT|TOOL=rejeitar_candidata.

Se a assinatura já existe, a ocorrência é incrementada em vez de criar um
problema conceitualmente novo.

======================================================================
6. POLÍTICAS INICIAIS SEGURAS
======================================================================

A migração V60 Workspace inclui cinco seeds:
1. API que exige credencial e não está configurada → SKIP_SOURCE.
2. ANIME + PokeAPI + universo != Pokémon → BLOCK_SOURCE.
3. ANIME + Bulbagarden + universo != Pokémon → BLOCK_SOURCE.
4. ANIME + Spriters Resource → não usar como rota genérica padrão.
5. Projeto >=100 itens → batch QA/relink 20, parallelism 8, skip waiting e
   delta snapshot.

Essas políticas são aprendidas/operacionais; não alteram CORE_RULE.

======================================================================
7. RESOLUÇÃO LOCAL / PERFORMANCE
======================================================================

O motor de políticas não cria uma chamada MCP por item.
Políticas ativas são resolvidas/cacheadas dentro do backend antes do roteamento.

O source routing:
1. monta contexto;
2. resolve políticas;
3. elimina fontes bloqueadas/sem configuração;
4. só então calcula score e fan-out;
5. registra outcome/telemetria.

Isso evita que mais paralelismo apenas multiplique rotas já conhecidas como
incorretas.
