3. SUPERVISOR EXCHANGE
======================================================================

Nova ferramenta principal:

supervisor_exchange

Ela:

- adquire/valida lease do Supervisor;
- aceita decisions[] + commands[] em lote;
- usa operation_id/idempotency;
- persiste decisões;
- cria SUPERVISOR_PLAN;
- cria branches em lote;
- sincroniza somente os itens tocados;
- ajusta candidate buffer;
- retorna ACK + estado compacto;
- NÃO executa coleta/download/materialização pesada dentro do round trip.

O trabalho pesado fica no plan tick/scheduler.

======================================================================
4. EXECUTAR ATÉ DIVERGÊNCIA
======================================================================

Nova ferramenta:

executar_ate_divergencia

Ela cria a intenção EXECUTE_UNTIL_DIVERGENCE e deixa o backend avançar por
plan ticks até:

- work packet/decision boundary;
- conclusão;
- erro real;
- limite operacional.

Um item em QA/relink/correção não bloqueia os demais.

======================================================================
5. FAN-OUT / FAN-IN
======================================================================

PLAN_BRANCH representa o trabalho derivado de uma ordem do Supervisor.

Tipos iniciais:

DISCOVERY
MATERIALIZATION
QA_PREP
RELINK
TECHNICAL_FIX
EXCEPTION

Branches são idempotentes e referenciam project_id/item_id.

O fan-in é feito comparando o branch com o estado canônico do item:

resolved → COMPLETED
QA/RELINK/technical real → WAITING_SUPERVISOR
waiting dependency → WAITING_DEPENDENCY
trabalho determinístico em curso → RUNNING.

======================================================================
6. ACK RÁPIDO / BACKGROUND DATA PLANE
======================================================================

supervisor_exchange não chama processAutomaticProject, executeCollection ou
materializeBatch no caminho da criação do plano.

O scheduled Worker executa:

runSupervisorWatchdog
runWorkerWatchdog
runSupervisorPlansTick

em paralelo.

O plan tick é que chama processAutomaticProject fora do round trip do
Supervisor.

======================================================================
7. SOURCE ROUTING P0
======================================================================

Foi implementado hard filter ANTES do score:

- configured
- source policy
- project_domain
- universe
- composition_class
- capability
- dependência externa

Depois do hard filter, o histórico/score pode ordenar as fontes restantes.

Fontes genéricas Openverse/Wikimedia/Pexels/Pixabay são fallback tardio para
ANIME e só entram após rodadas controladas.

PokeAPI/Bulbagarden/Spriters são classificados fora da rota ANIME.

Universos anime conhecidos corrigem GENERAL → ANIME como backstop de runtime.

======================================================================
8. DISCOVERY != MATERIALIZATION
======================================================================

O roteador mantém listas separadas:

eligible/discovery_sources
materialization_sources
fallback_sources
excluded_sources + reason

Uma fonte com can_materialize=true e can_discover=false pode continuar útil para
URL já conhecida, mas não é selecionada como mecanismo de discovery.

Foram criadas fontes diretas MediaWiki/Fandom para:

- Naruto
- My Hero Academia

sem dependência de Brave.

======================================================================
9. CANDIDATE BUFFER
======================================================================

Ao aceitar plano, a V60 eleva idempotentemente target_quantity dos termos do
escopo até o candidate_buffer_target configurado (padrão 3, máximo 5).

Objetivo:

rejeitou candidata 1
→ candidata 2/3 já pode existir
→ não voltar imediatamente à internet.

======================================================================
10. BACKPRESSURE
======================================================================

O data plane aceita max_qa_backlog.

O plan tick V60 usa backlog inicial 40.

Se waiting_qa_count atingir o limite, discovery/coleta nova desacelera, evitando
WIP/materialização ilimitada enquanto QA está congestionado.
