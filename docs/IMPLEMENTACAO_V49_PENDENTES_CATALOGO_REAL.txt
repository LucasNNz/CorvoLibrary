CORVO LIBRARY — V49
PENDENTES EM LOTE + MÉTRICAS REAIS DO CATÁLOGO
Data: 2026-08-27

OBJETIVO
=======
Separar corretamente Pendentes do Catálogo e permitir decisões em massa tanto pelo usuário quanto pelo Supervisor ChatGPT via MCP. Tornar os indicadores do topo do Catálogo derivados do D1 completo, e não da amostra carregada no navegador.

1. CATÁLOGO = SOMENTE APROVADOS
================================
Antes, a visualização Catálogo escondia apenas Rejeitados. Portanto Pendentes apareciam misturados com assets catalogados.

V49:
- Catálogo: status = Aprovado.
- Pendentes: status LIKE Pendente%.
- Rejeitados: status = Rejeitado.

Aprovar um Pendente altera:
- status -> Aprovado
- qa_status -> APROVADO

Após isso ele sai de Pendentes e passa a aparecer no Catálogo.

2. SELEÇÃO MANUAL EM MASSA
==========================
Na aba Pendentes:
- checkbox/ícone individual em cada asset;
- botão "Selecionar visíveis" para marcar o resultado filtrado;
- barra flutuante contextual com:
  * Aprovar -> Catálogo
  * Excluir definitivamente
  * Limpar seleção

A barra comum de lote/download/tags não é usada para Pendentes.

3. SELEÇÃO VISUAL PELA IA / MCP
================================
Novas ferramentas MCP:

obter_pendentes_para_qa_catalogo
- entrega até 20 arquivos físicos reais por chamada;
- usa /api/files/{asset_id} com código MCP e expiração;
- inclui __resources para inspeção visual real pelo ChatGPT;
- pode receber asset_ids específicos ou usar pendentes recentes.

aprovar_pendentes_em_lote
- recebe vários asset_ids escolhidos pelo Supervisor;
- só aprova registros que ainda estejam em Pendente*;
- move para o Catálogo em uma operação.

excluir_pendentes_permanentemente_em_lote
- recebe vários asset_ids;
- exige confirmar=true;
- só remove registros ainda Pendentes;
- operação irreversível.

Fluxo IA:
listar_pendentes
-> obter_pendentes_para_qa_catalogo
-> inspeção visual
-> escolher IDs
-> aprovar_pendentes_em_lote OU excluir_pendentes_permanentemente_em_lote

4. EXCLUSÃO PERMANENTE REAL
===========================
A exclusão da aba Pendentes não significa Rejeitar.

Ela remove:
- arquivo físico no R2;
- asset_usage;
- asset_consultations;
- batch_assets;
- referência linked_asset_id em automatic_project_items;
- registro final em assets.

Se a remoção física do R2 falhar, a exclusão de banco não continua silenciosamente.

5. MÉTRICAS REAIS DO CATÁLOGO
==============================
Novo helper compartilhado:
lib/asset-catalog-admin.ts

getCatalogStats() calcula diretamente no D1 completo:
- totalAssets: todos os registros físicos/catalogados no banco;
- catalogAssets: status Aprovado;
- universes: universos distintos entre Aprovados;
- pending: status Pendente*;
- rejected: Rejeitado;
- reused: Aprovados com use_count > 0;
- totalUses: soma de usos dos Aprovados.

Cards da interface:
TOTAL DE ASSETS = catalogAssets
UNIVERSOS = universes
PENDENTES = pending
REUTILIZADOS = reused

Esses números não usam mais allAssets.length nem Set sobre a lista limitada retornada ao browser.

6. API /api/assets
==================
GET
- devolve assets recentes para renderização;
- devolve stats calculados sobre o banco inteiro.

PATCH action=approve_pending
- aprovação manual em lote.

DELETE confirmar=true
- exclusão permanente dos Pendentes selecionados.

7. MCP — FONTE DE VERDADE

Assim interface e ChatGPT recebem os mesmos totais reais do D1.

Universos expostos no contexto MCP são agrupados somente entre assets Aprovados.
