FAST PUSH — ARQUIVOS DO CHAT + ASSETS DE PRODUÇÃO POR PROJETO

OBJETIVO

Expandir o FAST PUSH para permitir que diferentes agentes adicionem rapidamente arquivos e informações diretamente dentro de um projeto já existente.

A ideia é que o projeto deixe de guardar apenas ROTEIRO + IMAGENS e passe a funcionar como um pacote completo de produção, contendo:

- ROTEIRO
- IMAGENS DO ROTEIRO
- THUMBS
- IDEIAS DE TÍTULOS
- outros arquivos de apoio no futuro

Ao final, deve ser possível baixar o projeto inteiro em um único ZIP.


==================================================
1. ROTA PRINCIPAL — FAST PUSH POR URL
==================================================

A rota principal continua sendo a já existente:

URL pública encontrada
→ FAST PUSH por URL
→ Biblioteca baixa a mídia diretamente
→ salva no R2/D1
→ vincula ao projeto/item quando informado

Essa continua sendo a rota padrão e preferencial para imagens encontradas externamente.


==================================================
2. OPÇÃO SECUNDÁRIA — ARQUIVO JÁ PRESENTE NO CHAT
==================================================

Quando uma imagem ou arquivo já tiver sido trazido para o ambiente da conversa do ChatGPT, deve existir a opção de enviá-lo diretamente para a Biblioteca.

Fluxo:

arquivo já disponível no ChatGPT
→ FAST PUSH FILE
→ Biblioteca recebe o arquivo
→ salva uma única vez no R2
→ registra no D1
→ vincula ao projeto/item quando informado

Não deve ser necessário:

arquivo no chat
→ gerar URL temporária
→ baixar novamente
→ criar nova cópia
→ vincular

O arquivo já existente deve ser aproveitado diretamente.


==================================================
3. FAST PUSH DE IMAGENS DIRETO PARA ITEM DO PROJETO
==================================================

Quando o destino já for conhecido, a imagem deve entrar diretamente como candidata daquele item/PITEM.

Entrada possível:

- project_id
- item_projeto_id / PITEM
- target_file
- semantic_reference
- visual_reference
- arquivo ou URL

Fluxo:

imagem encontrada
→ FAST PUSH
→ projeto
→ item/PITEM correto
→ PARA_QA_VISUAL / PENDING_ANALYSIS

O analista depois apenas:

- APROVA
- REJEITA
- pede RELINK quando necessário

Pode haver várias candidatas anexadas ao mesmo item.


==================================================
4. FAST PUSH DE THUMBS DIRETO PARA O PROJETO
==================================================

Um agente especializado em thumbnails deve conseguir enviar suas propostas diretamente para o projeto.

Exemplo:

AGENTE DE THUMB
→ cria 2 ou 3 opções
→ FAST PUSH THUMB
→ projeto

Cada thumb deve ficar anexada ao projeto como candidata de thumbnail.

Campos sugeridos:

- project_id
- arquivo ou URL
- nome
- variante
- agente_origem
- observacao
- status

Exemplo de status:

THUMB_CANDIDATE
THUMB_APPROVED
THUMB_REJECTED

Exemplo:

thumb-a.png
thumb-b.png
thumb-c.png

As thumbs NÃO precisam estar vinculadas a um PITEM do roteiro.

Elas pertencem ao projeto como um todo.

O usuário, Supervisor ou outro analista pode depois:

- aprovar uma
- rejeitar as demais
- manter várias versões
- trocar a selecionada


==================================================
5. FAST PUSH DE IDEIAS DE TÍTULOS
==================================================

Um agente especializado em títulos deve conseguir anexar rapidamente 2 a 3 ideias de títulos ao projeto.

Não é necessário criar arquivo físico para cada título.

Os títulos podem ser registros estruturados ligados ao projeto.

Fluxo:

AGENTE DE TÍTULOS
→ gera 2 ou 3 ideias
→ FAST PUSH TITLES
→ projeto

Campos sugeridos:

- project_id
- texto
- variante
- agente_origem
- observacao
- score opcional
- status

Exemplo:

1. QUIZ: VOCÊ PASSARIA NO EXAME CHUNIN?
2. MONTE SEU TIME PARA O EXAME CHUNIN 🔥
3. VOCÊ SOBREVIVERIA AO EXAME CHUNIN?

Status sugeridos:

TITLE_CANDIDATE
TITLE_APPROVED
TITLE_REJECTED

O usuário, Supervisor ou analista pode:

- aprovar um título
- rejeitar títulos
- manter mais de um candidato
- alterar a escolha depois


==================================================
6. PROJETO COMO PACOTE COMPLETO DE PRODUÇÃO
==================================================

O projeto deve funcionar como container lógico de todos os componentes necessários para publicação.

Estrutura conceitual:

PROJECT

├── SCRIPT
│   └── roteiro.txt
│
├── REQUIREMENTS
│   └── imagens_necessarias.txt
│
├── IMAGES
│   ├── 001-naruto.jpg
│   ├── 002-sasuke.jpg
│   └── ...
│
├── THUMBS
│   ├── thumb-a.png
│   ├── thumb-b.png
│   └── thumb-c.png
│
├── TITLES
│   ├── candidato-01
│   ├── candidato-02
│   └── candidato-03
│
└── METADATA
    ├── titulo_aprovado
    ├── thumb_aprovada
    ├── status
    └── histórico


==================================================
7. EXPORTAÇÃO SIMPLES DO PROJETO
==================================================

Deve existir uma operação simples para baixar o projeto completo.

Exemplo:

EXPORT PROJECT ZIP

Entrada:

- project_id

Saída:

PROJETO_NARUTO_CHUNIN.zip

Estrutura sugerida:

PROJETO_NARUTO_CHUNIN.zip

├── ROTEIRO.txt
├── IMAGENS_NECESSARIAS.txt
│
├── IMAGENS/
│   ├── 001-...
│   ├── 002-...
│   └── ...
│
├── THUMBS/
│   ├── thumb-a.png
│   ├── thumb-b.png
│   └── thumb-c.png
│
├── TITULOS.txt
│
└── PROJETO.json


==================================================
8. TITULOS.txt
==================================================

O ZIP deve gerar automaticamente um TITULOS.txt.

Exemplo:

TÍTULO APROVADO:
MONTE SEU TIME PARA O EXAME CHUNIN 🔥

OUTRAS IDEIAS:

1. QUIZ: VOCÊ PASSARIA NO EXAME CHUNIN?
2. VOCÊ SOBREVIVERIA AO EXAME CHUNIN?


==================================================
9. PROJETO.json
==================================================

O ZIP também pode incluir um arquivo simples de metadados.

Exemplo de informações:

- project_id
- nome
- universo
- status
- título aprovado
- thumb aprovada
- quantidade de imagens
- data da exportação
- versões dos arquivos
- agentes que contribuíram


==================================================
10. PRINCÍPIO OPERACIONAL
==================================================

Cada agente deve poder contribuir diretamente para o MESMO projeto sem precisar criar projetos paralelos.

Exemplo:

Agente Roteiro
→ anexa roteiro

Agente Imagens
→ FAST PUSH imagens

Agente Thumb
→ FAST PUSH 2 ou 3 thumbs

Agente Títulos
→ FAST PUSH 2 ou 3 títulos

Analista
→ aprova/rejeita candidatas

Biblioteca
→ mantém tudo persistido e organizado

No final:

PROJETO
→ EXPORTAR ZIP
→ roteiro + imagens + thumbs + títulos


==================================================
11. RESULTADO ESPERADO
==================================================

Transformar cada projeto da Biblioteca em uma unidade completa de produção.

O objetivo é que diferentes agentes possam trabalhar em paralelo e simplesmente EMPURRAR seus resultados para o mesmo projeto.

A Biblioteca fica responsável por:

- persistir
- organizar
- versionar
- manter candidatos
- registrar aprovados/rejeitados
- exportar o pacote final

Sem exigir que cada agente conheça ou execute toda a pipeline.

O fluxo final desejado é:

AGENTES
→ FAST PUSH
→ PROJETO CENTRAL
→ QA / ESCOLHA
→ EXPORT PROJECT ZIP

Resultado:

um único ZIP contendo tudo necessário para a etapa seguinte de produção:
TÍTULO + THUMB + ROTEIRO + IMAGENS.
