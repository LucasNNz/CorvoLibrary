CORVO LIBRARY V47 — PONTE MATERIALIZACAO -> SUPERVISOR MCP
Data: 2026-08-27

OBJETIVO
Fechar a lacuna em que uma candidata real podia estar materializada no R2 e pronta para QA tecnico, mas nao aparecer no Supervisor do projeto principal por ter sido produzida em lote lateral/manual ou por nao carregar o vinculo completo do projeto.

FLUXO IMPLEMENTADO
READY_FOR_VISUAL_QA
-> resolver projeto + item
-> registrar supervisor_project_candidates
-> primeira candidata do item = PARA_QA_VISUAL
-> demais candidatas do item = PARA_ANALISE
-> vincular project_id + item_id + materialization ids + arquivo + fonte + URL + host + metadata
-> criar/atualizar QA_VISUAL em supervisor_decision_queue
-> obter_candidatas_qa_visual entrega o arquivo real
-> decisao do Supervisor volta para o mesmo item

BACKFILL / RECONCILIACAO
- reconciliar_projeto_automatico agora procura materializacoes READY_FOR_VISUAL_QA, inclusive de rotas laterais/manuais.
- obter_estado_supervisor e obter_candidatas_qa_visual executam reconciliacao antes de responder.
- o matcher usa evidencias de projeto, item, target filename, item key, conceito/referencia e universo.
- vinculos ambiguos ou com score insuficiente nao sao criados automaticamente.
- projetos concluidos/cancelados e itens congelados nao sao reabertos.

ESTADOS DA PONTE
- PARA_ANALISE
- PARA_QA_VISUAL
- APROVADO
- REJEITADO
- RELINK_REQUIRED
- CORRECAO_TECNICA_PERMITIDA
- DESCARTADO_RELINK

PROMOCAO AUTOMATICA
Somente uma candidata por item fica ativa em PARA_QA_VISUAL.
Se ela for REJEITADA, a candidata mais antiga em PARA_ANALISE do mesmo item e promovida automaticamente para PARA_QA_VISUAL, o automatic_project_item recebe os novos IDs de materializacao e uma nova decisao QA_VISUAL e criada.

RELINK
Ao receber RELINK_REQUIRED, a candidata ativa e marcada como RELINK_REQUIRED e as candidatas ainda em PARA_ANALISE daquele item sao marcadas DESCARTADO_RELINK, evitando reapresentar a mesma rota quando o Supervisor decidiu buscar outra referencia/fonte.

MATERIALIZACAO NOVA
lib/materializer.ts chama a ponte assim que um item termina em READY_FOR_VISUAL_QA e tambem apos recuperacao de arquivo ja existente no R2.
materializar_url ganhou os parametros opcionais projeto_id e item_projeto_id para vinculo explicito quando a chamada conhece o projeto principal.

COLETA DO PROJETO
syncProjectFromCollection passa a chamar a mesma ponte com projectId, itemId e collectionCandidateId explicitos. Uma candidata adicional nao sobrescreve a candidata que ja esta ativa no QA; ela entra em PARA_ANALISE.

SUPERVISOR MCP
- obter_candidatas_qa_visual agora le supervisor_project_candidates/ PARA_QA_VISUAL e entrega arquivo real + contexto completo.
- obter_estado_supervisor mostra candidatas reconciliadas, PARA_ANALISE e PARA_QA_VISUAL, alem da camada de coleta.
- syncDecisionQueue usa o ID persistente da candidata da ponte.
- decisoes QA preservam a nova decisao pendente quando uma rejeicao promove a proxima candidata.

RESULTADO ESPERADO PARA O CASO MHA
Ao consultar o projeto principal, a reconciliacao procura as materializacoes reais ainda em READY_FOR_VISUAL_QA. Se houver correspondencia inequivoca com os targets/itens do MHA, elas passam a aparecer em obter_candidatas_qa_visual sem precisar produzir novamente os arquivos. A decisao tomada pelo Supervisor fica vinculada ao mesmo item do projeto.

REGRA DE SEGURANCA
A ponte nunca transforma MATERIALIZADO em APROVADO. Ela apenas torna a candidata real visivel ao Supervisor. A aprovacao continua exigindo QA visual/decisao explicita, e aprovados/congelados nao sao reabertos.
