MODO PUSH RÁPIDO EM LOTE — BIBLIOTECA SEMÂNTICA
Versão de especificação operacional

OBJETIVO
Destravar a operação de coleta permitindo que o Supervisor/GPT envie rapidamente muitas imagens encontradas na web para dentro da Biblioteca, sem obrigar decisão visual final na borda e sem passar pelo materializador usual pesado.

PRINCÍPIO
Buscar rápido → empurrar várias opções → salvar no R2/D1 → analisar depois.

A imagem não precisa estar aprovada para entrar.
Ela entra como candidata com tags e contexto suficientes para ser analisada posteriormente pela IA ou manualmente pelo usuário.

FLUXO NOVO — FAST PUSH BATCH

1. Supervisor/GPT recebe uma necessidade visual.
2. Faz a linkagem semântica:
   - universo
   - personagem/objeto/cenário
   - cena provável
   - arco/evento/episódio provável quando aplicável
   - termos inclusivos de busca
   - slot/referência do roteiro
3. Busca várias opções na web.
4. Não precisa escolher uma vencedora.
5. Envia em lote o máximo de candidatas úteis encontradas.
6. Biblioteca:
   - baixa cada URL;
   - valida MIME/arquivo real;
   - calcula SHA-256;
   - detecta duplicata;
   - salva no R2;
   - cria registro de candidata no D1;
   - preserva URL/fonte;
   - aplica tags e contexto;
   - marca como PENDING_ANALYSIS.
7. Depois, uma das três rotas pode acontecer:
   A) Analisador IA aprova/rejeita.
   B) Usuário aprova/rejeita manualmente.
   C) Supervisor GPT aprova/rejeita em QA visual.
8. Candidata aprovada é promovida para asset permanente e pode resolver o slot/projeto.
9. Candidata rejeitada permanece registrada ou é descartada conforme política.

REGRA PRINCIPAL
FAST PUSH não tenta encontrar “a imagem perfeita”.
Sua função é apenas colocar rapidamente boas opções dentro da Biblioteca.

NÃO FAZER NO FAST PUSH
- não rodar busca iterativa pesada;
- não abrir RELINK por falha semântica;
- não insistir em várias rodadas;
- não exigir QA antes de salvar;
- não exigir aprovação antes da ingestão;
- não bloquear o lote inteiro se um item falhar;
- não usar o materializador usual quando o Supervisor já possui URLs de candidatas.

ENTRADA IDEAL — LOTE
Endpoint sugerido:
importar_candidatas_url_lote

Cada item deve aceitar, no mínimo:

- operation_id

- subject
- concept
- visual_reference

- tags
- used_for
- priority
- metadata de busca opcional

COMPORTAMENTO DO LOTE
O lote deve ser parcial e independente por item.

Exemplo de retorno:

1 | INGESTED
2 | INGESTED
3 | DUPLICATE_REUSED
4 | FAILED_HTTP_404
5 | INGESTED
6 | INGESTED
7 | FAILED_INVALID_MIME
8 | INGESTED
9 | INGESTED
10 | INGESTED

Uma falha nunca cancela os demais itens.

DEDUPLICAÇÃO
Antes de criar novo asset/candidata definitiva:

URL → download → SHA-256 → procurar duplicata

Se SHA já existir:
- não duplicar arquivo físico;
- reutilizar asset/candidata existente quando compatível;
- registrar novo uso/projeto/slot;
- retornar DUPLICATE_REUSED.

MODOS DE ANÁLISE

1. ANALISADOR IA
A Biblioteca pode rodar depois um analisador visual em lote:
- personagem correto;
- universo correto;
- aderência à cena;
- qualidade visual;
- resolução;
- watermark;
- composição;
- duplicidade visual;
- transparência quando exigida;
- adequação ao slot.

2. APROVAÇÃO MANUAL PELO USUÁRIO
O usuário deve poder abrir a Inbox de candidatas e:
- aprovar;
- rejeitar;
- selecionar uma entre várias;
- aprovar várias em lote;
- rejeitar várias em lote;
- substituir a vencedora;
- ver referência do roteiro, tags, fonte e slot.

A decisão manual deve ter precedência sobre análise automática.

3. QA PELO SUPERVISOR GPT
O Supervisor pode obter várias candidatas reais do R2, inspecionar visualmente e:
- APROVAR;
- REJEITAR;
- deixar para análise posterior;
- pedir nova coleta apenas quando necessário.

INBOX VISUAL
Criar uma área lógica “Inbox de candidatas”.

Filtros desejados:
- projeto
- universo
- personagem
- slot
- cena
- status
- fonte
- lote
- analisado/não analisado

Cada card deve mostrar:
- preview;
- personagem/sujeito;
- cena/referência;
- tags;
- fonte;
- projeto/slot;
- status;
- Aprovar;
- Rejeitar.

PROMOÇÃO
Somente depois da aprovação:

PENDING_ANALYSIS
→ APPROVED_CANDIDATE
→ PROMOTED_TO_ASSET

Ao promover:
- asset permanente no catálogo;
- vínculo com projeto/slot;
- histórico de uso;
- semanticFamily quando aplicável;
- origem e URL preservadas.

ROTA MANUAL
Usuário pode a qualquer momento:

PENDING_ANALYSIS
→ APROVAR MANUALMENTE
ou
→ REJEITAR MANUALMENTE

Não é obrigatório esperar o analisador automático.

FAST PUSH VS MATERIALIZADOR USUAL

FAST PUSH:
- recebe URLs já encontradas;
- baixa uma vez;
- salva;
- tagueia;
- deixa decisão para depois;
- alta vazão;
- ideal para lote.

MATERIALIZADOR USUAL:
- tenta resolver candidatas;
- gerencia cursor/tentativas;
- pode relinkar;
- pode repetir fontes;
- QA acoplado;
- mais lento;
- permanece como fallback para casos não resolvidos.

REGRA DE ROTEAMENTO

Se Supervisor/GPT já encontrou URLs úteis:
→ FAST PUSH BATCH.

Se arquivo já está no chat:
→ FAST PUSH FILE.

Se SHA já existe:
→ REUSE + REGISTER_USAGE.

Se não existem candidatas conhecidas:
→ materializador/coletor usual como fallback.

META OPERACIONAL
Permitir que o Supervisor envie 10, 20 ou mais candidatas em uma única chamada, limitado apenas por um teto seguro do backend.

Meta inicial sugerida:
- 20 itens por chamada;
- processamento paralelo interno;
- retorno por item;
- idempotência por operation_id;
- persistência imediata conforme cada item termina.

PRINCÍPIO DE PERFORMANCE
A ingestão não deve esperar o QA.

Enquanto:
- o lote 1 está sendo analisado,
- o lote 2 pode estar sendo ingerido,
- o Supervisor pode buscar o lote 3,
- o usuário pode aprovar manualmente outro conjunto.

Tudo deve trabalhar em paralelo sobre o mesmo projeto.

MODO “BATE-PRONTO”
Fluxo recomendado para desbloquear operação:

LINKADOR
→ gera contexto de localização

BUSCA WEB / YOUTUBE / OUTRAS FONTES
→ encontra várias opções

FAST PUSH BATCH
→ envia todas as opções úteis

INBOX
→ PENDING_ANALYSIS

ANALISADOR IA / USUÁRIO / SUPERVISOR
→ aprova ou rejeita

CATÁLOGO
→ promove aprovadas

PROJETO
→ registra resolução do slot

PRIORIDADE DE IMPLEMENTAÇÃO

P0 — importar_candidatas_url_lote
P0 — Inbox PENDING_ANALYSIS
P0 — aprovação/rejeição manual
P0 — deduplicação por SHA
P0 — retorno independente por item
P0 — idempotência por operation_id

P1 — analisador IA em lote
P1 — promover aprovadas em lote
P1 — registrar uso automaticamente
P1 — filtros por projeto/slot/personagem

P2 — memória de fonte/query/cena
P2 — integração com YouTube Frame Locator
P2 — ranking automático das candidatas

RESULTADO ESPERADO
Substituir o gargalo atual:

BUSCAR → MATERIALIZAR PESADO → QA → REPETIR

por:

BUSCAR MUITAS → EMPURRAR MUITAS → CONTINUAR TRABALHANDO

enquanto a Biblioteca faz depois:

ANALISAR → APROVAR/REJEITAR → PROMOVER.

A aprovação pode ser automática, feita pelo Supervisor GPT ou manualmente pelo usuário.

OBJETIVO FINAL
Maximizar vazão de ingestão e evitar que o Supervisor fique bloqueado tentando decidir ou materializar uma candidata por vez.
