CORVO LIBRARY V38 — IMPLEMENTAÇÃO DO SUPERVISOR IA / ESPECIFICAÇÃO V1.1
DATA: 2026-08-26
BASE: CORVO_LIBRARY_V37_ATUAL

OBJETIVO
Implementar no código da V37 as regras do arquivo ESPECIFICACAO_SUPERVISOR_IA_BIBLIOTECA9_V1_1.txt, preservando o pipeline existente e adicionando as camadas semânticas e de consistência operacional.

IMPLEMENTADO
1. SUPERVISOR IA
- Novo módulo: lib/ai-supervisor.ts
- Novo endpoint owner-only: POST /api/ai/supervisor
- Contrato fixo de entrada/saída.
- Classificação semântica e CONTEXTUAL/ISOLATED.
- Search planning com consultas, termos negativos e preferência de fontes.
- Relink automático após esgotamento de rota.
- QA visual automático quando SUPERVISOR_IA_ENDPOINT estiver configurado.
- Sem provedor, o fallback determinístico planeja busca/relink, mas NÃO inventa aprovação visual.
- Falha do provedor é isolada e cai em fallback seguro.

2. IDEMPOTÊNCIA
- Hash SHA-256 de SCRIPT e REQUIREMENTS.
- Reuso do mesmo arquivo/hash.
- Índice único seguro para project+role+content_hash (linhas históricas ficam NULL).
- IDs determinísticos de itens por project+version+item_key.
- Colapso de duplicatas históricas no preparo da versão, preservando eventos e vínculos de seed.

3. FAMÍLIAS SEMÂNTICAS / FAN-OUT
- family_id e family_seed_item_id por item.
- Somente a seed faz busca/QA quando os slots são equivalentes.
- Asset aprovado da seed faz fan-out para os slots compatíveis.
- Cada slot mantém target file e registro de uso próprios.

4. RECONCILIAÇÃO DE ESTADO
- Nova função reconcileAutomaticProject / ferramenta reconciliar_projeto_automatico.
- Reconcilia item do projeto com materialization item congelado.
- Recupera também lote manual/alternativo pelo projeto + target file quando houver asset congelado.
- Recalcula resolvidos, status e progresso sem apagar histórico.

5. CHUNKING
- Consultas grandes de assets/termos/materializações são divididas em blocos de até 40.
- Exportação e reconciliação não dependem de um IN(...) gigante.

6. TARGET FILE COMO VERDADE DA EXPORTAÇÃO
- ZIP do projeto usa target_file do REQUIREMENTS.
- Um mesmo asset pode aparecer várias vezes no ZIP com nomes diferentes.
- Bytes podem ser reutilizados em cache, mas os target files continuam distintos.
- ZIP inclui IMPORTACAO.txt e PROJETO.txt.
- Exportador do Materializador suporta subconjunto real: ao pedir 20 itens, valida/exporta só os 20.
- Exportação parcial não marca o lote inteiro como EXPORTED.

7. GATE FINAL
- Nova função getProjectConsistencyGate / ferramenta validar_consistencia_projeto.
- Verifica target files esperados/resolvidos, assets, objetos R2, duplicatas e pendências.
- Quando ZIP automático está ativo, verifica metadados do ZIP, missing=0 e presença de IMPORTACAO.txt.
- COMPLETED somente com gate final aprovado.
- Encerramento forçado com pendências usa FORCED_CLOSED.

8. CONTEXTUAL VS ISOLATED
- composition_class persistido no projeto e no materializador.
- Correção técnica permitida somente para ISOLATED.
- CONTEXTUAL não pode ser transformado em cena por montagem técnica.

9. LINHAGEM TÉCNICA
- materialization_candidates: parent_file_id, technical_operation, technical_parameters.
- materialization_files: source_file_id, technical_operation, technical_parameters.
- IMPORTACAO.txt exporta a linhagem.

10. FONTES / MEMÓRIA / FALHAS
- source_plan por termo; ordem de fontes pode variar conforme plano do supervisor.
- Fonte sem segredo: SOURCE_NOT_CONFIGURED, SKIPPED, não consome rodada nem falha do item.
- URL/candidata já vista continua descartada pelo histórico do lote.
- strategy_state registra histórico de queries, candidatas e falhas.
- Após esgotar orçamento sem solução: FAILED_SEMANTIC.
- Falha técnica isolada: FAILED_INFRASTRUCTURE.
- PARA_ANALISE só é usado pelo coletor quando houve materialização real.

11. PROBE CONTROLADA / CIRCUIT BREAKER
- Nova tabela materialization_host_probes.
- Nova função/ferramenta probar_url_controlada.
- Probe explícita pode testar host com circuit breaker aberto.
- Resultado atualiza saúde e fica registrado.
- Mesma URL não pode ser probada novamente dentro da janela de 5 minutos sem forcar=true.

CONFIGURAÇÃO OPCIONAL DO PROVEDOR IA
SUPERVISOR_IA_ENDPOINT = endpoint HTTP que recebe o contrato do supervisor e devolve o contrato de saída.
SUPERVISOR_IA_TOKEN = Bearer token opcional.

- QA visual permanece pendente e exige decisão humana;
- nenhuma imagem é aprovada visualmente por heurística.
