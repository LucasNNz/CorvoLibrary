ESPECIFICAÇÃO — SUPERVISOR IA DENTRO DA BIBLIOTECA SEMÂNTICA 9
VERSÃO: 1.0
OBJETIVO: LEVAR PARA DENTRO DA BIBLIOTECA 9 A MESMA LÓGICA DE SUPERVISÃO, RELINKAGEM, TROCA DE URL, TROCA DE CONSULTA, TROCA DE FONTE E DECISÃO DE QA QUE HOJE É FEITA NO CHAT.

=====================================================================
1. OBJETIVO GERAL
=====================================================================
A BIBLIOTECA SEMÂNTICA 9 NÃO DEVE DEPENDER DO CHAT PARA TOMAR AS DECISÕES LONGAS DO PROCESSO.

ELA DEVE CONSEGUIR:
- RECEBER SCRIPT E REQUIREMENTS;
- INTERPRETAR CADA ITEM SEMÂNTICO;
- LINKAR O ITEM A UMA REFERÊNCIA CONHECIDA;
- DECIDIR SE USA BIBLIOTECA OU COLETA EXTERNA;
- GERAR E REGERAR CONSULTAS DE BUSCA;
- ESCOLHER, TROCAR OU DESCARTAR URLS;
- TROCAR DE FONTE QUANDO NECESSÁRIO;
- AVALIAR CANDIDATAS;
- MATERIALIZAR;
- FAZER QA TÉCNICO;
- ACIONAR QA VISUAL POR IA;
- APROVAR, CONGELAR OU RELINKAR;
- CATALOGAR O APROVADO;
- FECHAR O PROJETO APENAS QUANDO ESTIVER REALMENTE RESOLVIDO.

A CAMADA NOVA NECESSÁRIA É UM SUPERVISOR IA ORQUESTRADOR.

=====================================================================
2. PAPEL DO SUPERVISOR IA
=====================================================================
O SUPERVISOR IA É O CÉREBRO DE DECISÃO DA ESTEIRA.

ELE NÃO DEVE GERAR IMAGENS.
ELE NÃO DEVE CRIAR FUNDO.
ELE NÃO DEVE COMBINAR CENAS.
ELE NÃO DEVE FAZER COMPOSIÇÃO CRIATIVA.

ELE DEVE:
- INTERPRETAR O SIGNIFICADO REAL DO ITEM;
- ESCOLHER A REFERÊNCIA CORRETA;
- DEFINIR COMO PESQUISAR;
- DECIDIR QUAL FONTE TENTAR PRIMEIRO;
- DECIDIR QUANDO DESCARTAR UMA ROTA;
- DECIDIR QUANDO RELINKAR COMPLETAMENTE O ITEM;
- DECIDIR SE O RESULTADO PASSA OU NÃO PASSA NO QA VISUAL;
- DECIDIR A AÇÃO SEGUINTE;
- COMANDAR TROCAS DE URL, CONSULTA, FONTE, REFERÊNCIA E ROTA.

EM OUTRAS PALAVRAS:
A IA COMANDA A ESTRATÉGIA.
A BIBLIOTECA EXECUTA A ESTRATÉGIA.

=====================================================================
3. REGRA DE OURO
=====================================================================
NÃO CRIAR O QUE O ROTEIRO PEDE.
ENCONTRAR ONDE AQUILO JÁ EXISTE.

SE UMA REFERÊNCIA OU CANDIDATA ESTIVER ERRADA:
- NÃO “SALVAR” SEMANTICAMENTE;
- NÃO FORÇAR EDIÇÃO CRIATIVA;
- DESCARTAR;
- RESELECIONAR REFERÊNCIA;
- RELINKAR;
- BUSCAR NOVAMENTE.

AJUSTES TÉCNICOS PERMITIDOS APENAS QUANDO O CONTEÚDO JÁ ESTIVER CERTO:
- CROP;
- RESIZE;
- UPSCALE TÉCNICO;
- CONVERSÃO DE FORMATO;
- REMOÇÃO DE FUNDO QUANDO O PRESET EXIGIR TRANSPARÊNCIA;
- LIMPEZA LEVE DE HALO / ALPHA / FRAGMENTOS;
- COMPRESSÃO.

=====================================================================
4. DIFERENÇA ENTRE O MOTOR ATUAL E O MOTOR DESEJADO
=====================================================================
HOJE A BIBLIOTECA JÁ TEM:
- PROJETOS;
- ARQUIVOS SCRIPT/REQUIREMENTS;
- ITENS PERSISTIDOS;
- BUSCA EXTERNA;
- FONTES CONFIGURÁVEIS;
- MATERIALIZAÇÃO;
- QA TÉCNICO;
- CONGELAMENTO;
- CATALOGAÇÃO;
- TELEMETRIA;
- ZIP.

O QUE FALTA É A CAMADA DE DECISÃO SEMÂNTICA.

A ESTEIRA DESEJADA PASSA A SER:
SCRIPT + REQUIREMENTS
-> NORMALIZAÇÃO
-> LINKAGEM IA
-> VERIFICAÇÃO DE MATURIDADE DA BIBLIOTECA
-> PLANEJAMENTO DE BUSCA IA
-> DESCOBERTA / COLETA
-> RANQUEAMENTO DE CANDIDATAS
-> MATERIALIZAÇÃO
-> QA TÉCNICO
-> QA VISUAL POR IA
-> APROVAR / PRÓXIMA CANDIDATA / RELINKAR
-> CONGELAR
-> CATALOGAR
-> ZIP

6. REGRA DA MATURIDADE DA BIBLIOTECA
=====================================================================
PARA CADA ITEM SEMÂNTICO:
- SE JÁ EXISTIREM 5 VARIAÇÕES PRÓXIMAS APROVADAS, A BIBLIOTECA DEVE SER TENTADA PRIMEIRO;
- SE AINDA NÃO EXISTIREM 5 VARIAÇÕES PRÓXIMAS APROVADAS, NÃO USAR A BIBLIOTECA COMO FONTE PRINCIPAL;
- NESSE CASO, FAZER COLETA EXTERNA NORMAL;
- APÓS APROVAR O ASSET, IMPORTAR/CATALOGAR PARA A BIBLIOTECA.

PORTANTO O FLUXO É:
LINKAGEM
-> CONSULTA À BIBLIOTECA
-> MATUREZA >= 5 ?
   SIM -> LIBRARY_FIRST
   NÃO -> EXTERNAL_FIRST

11. SEPARAÇÃO OBRIGATÓRIA DAS FALHAS
=====================================================================
NEM TODA FALHA É IGUAL.
O SISTEMA PRECISA ROTULAR A FALHA, PORQUE ISSO DEFINE A AÇÃO SEGUINTE.

TIPOS SUGERIDOS:
- SOURCE_NOT_CONFIGURED
- SOURCE_TIMEOUT
- SOURCE_EMPTY
- BAD_QUERY
- BAD_REFERENCE
- MATERIALIZATION_FAILURE
- TECHNICAL_FIXABLE
- TECHNICAL_UNFIXABLE
- WRONG_CHARACTER
- WRONG_OBJECT
- WRONG_SCENE
- WRONG_BACKGROUND
- WRONG_PRESET
- WATERMARK
- LOW_QUALITY
- DUPLICATE_CANDIDATE
- RELINK_REQUIRED

REGRAS:
- SOURCE_NOT_CONFIGURED -> NÃO CONSUME RODADA; PULAR FONTE
- SOURCE_TIMEOUT -> TROCAR FONTE OU HOST
- SOURCE_EMPTY -> TROCAR QUERY
- BAD_QUERY -> GERAR NOVA QUERY
- BAD_REFERENCE -> RELINK
- MATERIALIZATION_FAILURE -> PRÓXIMA CANDIDATA / PRÓXIMA URL
- TECHNICAL_FIXABLE -> EXECUTAR CORREÇÃO TÉCNICA
- WRONG_CHARACTER / WRONG_CONCEPT -> DESCARTAR CANDIDATA
- WATERMARK -> DESCARTAR CANDIDATA
- LOW_QUALITY -> DESCARTAR CANDIDATA
- RELINK_REQUIRED -> NOVA REFERÊNCIA

12. REGRAS IMPORTANTES PARA OS ESTADOS
=====================================================================
ALGUNS ESTADOS PRECISAM SER MAIS RÍGIDOS.

REGRA 1:
PARA_ANALISE SÓ PODE EXISTIR SE HOUVER ARQUIVO REAL MATERIALIZADO.

CONDIÇÕES MÍNIMAS:
- MATERIALIZATION_ID != NULL
- OBJETO REAL NO R2
- MIME VÁLIDO
- BYTES > MÍNIMO
- LARGURA E ALTURA VÁLIDAS
- STATUS TÉCNICO APTO

SE NÃO HOUVER ARQUIVO REAL, NÃO USAR PARA_ANALISE.
USAR:
- MATERIALIZATION_REQUIRED
- SEARCH_EXHAUSTED
- INSUFICIENTE

REGRA 2:
COMPLETED SÓ PODE SER USADO QUANDO NÃO HOUVER PENDÊNCIA REAL.

SE HOUVER ENCERRAMENTO FORÇADO, USAR:
- FORCED_CLOSED

20. CICLO AUTOMÁTICO DE EXECUÇÃO
=====================================================================
A BIBLIOTECA DEVE FUNCIONAR EM LOOP AUTOMÁTICO POR ITEM.

PSEUDOFLUXO:
1. ITEM_START
2. CHAMAR IA PARA LINKAGEM
3. CONSULTAR MATURIDADE DA BIBLIOTECA
4. SE >= 5, TENTAR BIBLIOTECA
5. SE NÃO RESOLVER, CHAMAR IA PARA SEARCH_PLAN
6. COLETAR / DESCOBRIR
7. RANQUEAR CANDIDATAS
8. MATERIALIZAR A MELHOR
9. FAZER QA TÉCNICO
10. ENVIAR PARA QA VISUAL IA
11. SE APROVAR -> FREEZE -> CATALOGAR
12. SE REPROVAR POR CANDIDATA -> PRÓXIMA CANDIDATA
13. SE REPROVAR POR REFERÊNCIA -> RELINK
14. REPETIR ATÉ RESOLVER OU ESGOTAR ORÇAMENTO
15. FECHAR ITEM
16. QUANDO TODOS OS ITENS ESTIVEREM FECHADOS, EXPORTAR ZIP

=====================================================================
21. REGRAS DE CUSTO E ORÇAMENTO
=====================================================================
O SUPERVISOR IA DEVE RESPEITAR CUSTO X BENEFÍCIO.

REGRAS SUGERIDAS:
- APÓS 2 TENTATIVAS TÉCNICAS SEM MELHORA, NÃO INSISTIR NA MESMA ROTA;
- APÓS ESGOTAR CONSULTAS DA MESMA REFERÊNCIA SEM GANHO, RELINKAR;
- SE UMA FONTE ESTIVER LENTA OU FALHA, TROCAR RÁPIDO;
- SE O HOST ESTIVER RUIM, EVITAR REPETIÇÃO;
- SE JÁ EXISTE ASSET APROVADO ADEQUADO, CONGELAR E SEGUIR;
- NÃO REABRIR ITEM CONGELADO POR CAUSA DE FALHAS EM OUTRO ITEM.

=====================================================================
22. ESTADOS TERMINAIS RECOMENDADOS
=====================================================================
POR ITEM:
- FROZEN
- CANCELLED
- FAILED_SEMANTIC
- FAILED_INFRASTRUCTURE

POR PROJETO:
- COMPLETED
- COMPLETED_WITH_WARNINGS
- FORCED_CLOSED
- FAILED

REGRAS:
- COMPLETED = TODOS OS ITENS OBRIGATÓRIOS RESOLVIDOS;
- COMPLETED_WITH_WARNINGS = RESOLVIDO, MAS COM OBSERVAÇÕES NÃO CRÍTICAS;
- FORCED_CLOSED = ENCERRADO MANUALMENTE COM PENDÊNCIAS;

31. CONTEXTUAL VS ISOLATED — REGRA FORMAL DO SUPERVISOR
=====================================================================
O SUPERVISOR IA DEVE CLASSIFICAR O ITEM COMO CONTEXTUAL OU ISOLATED ANTES DE ACEITAR CORREÇÕES TÉCNICAS.

ISOLATED:
- PERSONAGEM/OBJETO/EFEITO SEM FUNDO;
- PODE USAR PNG/RENDER PRONTO;
- PODE REMOVER SOMENTE FUNDO SIMPLES;
- PODE FAZER ALPHA, HALO, FEATHER, CROP, RESIZE, UPSCALE, CONVERSÃO.

CONTEXTUAL:
- PERSONAGEM/OBJETO + AÇÃO + CENÁRIO PRECISAM JÁ EXISTIR JUNTOS NA IMAGEM;
- NÃO PODE MONTAR CENA;
- NÃO PODE COMBINAR PERSONAGENS;
- NÃO PODE CRIAR FUNDO;
- NÃO PODE TRANSFORMAR UMA IMAGEM ISOLADA EM CONTEXTUAL;
- SE O CONTEXTO NÃO EXISTIR NA FONTE, RELINKAR.

EXEMPLOS DE REJEIÇÃO CONTEXTUAL:
- DUPLA QUE NÃO ESTÁ JUNTA NA MESMA IMAGEM;
- PERSONAGEM ISOLADO EM FUNDO BRANCO PARA SLOT DE CENA;
- PAINEL DE MANGÁ COM BALÕES/TEXTO QUANDO O SLOT PEDE CENA LIMPA;
- REFERÊNCIA QUE COMUNICA O OBJETO, MAS NÃO A AÇÃO/CENÁRIO EXIGIDOS.

CAMPO OBRIGATÓRIO SUGERIDO:
"composition_class": "CONTEXTUAL | ISOLATED"
