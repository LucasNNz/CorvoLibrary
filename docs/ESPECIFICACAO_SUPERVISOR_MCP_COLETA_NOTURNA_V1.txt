ESPECIFICACAO — SUPERVISOR IA VIA MCP + COLETA AUTONOMA NOTURNA
Corvo Library / Biblioteca Semantica
Versao conceitual consolidada
Data: 2026-08-27

======================================================================
1. OBJETIVO
======================================================================

Substituir o Supervisor IA interno baseado em modelos Cloudflare
(Qwen, Llama etc.) por uma arquitetura mais simples:

- o APP/BIBLIOTECA executa;
- o MCP expoe estado, evidencias e controles;
- o ChatGPT atua como Supervisor operacional;
- a coleta automatica pode continuar funcionando sem IA;
- o QA visual e decisoes adaptativas podem ser feitos pelo ChatGPT via MCP;
- configuracoes eficientes descobertas durante a operacao podem ser salvas
  e reutilizadas nas proximas execucoes.

A ideia central e:

BIBLIOTECA = MEMORIA + EXECUTOR + COLETOR
MCP        = SISTEMA DE CONTROLE
CHATGPT    = SUPERVISOR
CLOUDFLARE AI / LLAMA / QWEN = NAO OBRIGATORIOS

======================================================================
2. ALTERACAO PRINCIPAL DO SUPERVISOR
======================================================================

O campo atual de Supervisor IA nao deve mais representar:

- escolha de modelo;
- Qwen;
- Llama;
- Workers AI;
- consumo de Neurons;
- JSON Mode;
- provider Cloudflare;
- licenca do Llama.

O Supervisor IA passa a ser apenas uma funcao:

SUPERVISOR IA
[ LIGADO / DESLIGADO ]

Significado:

SUPERVISOR IA = DESLIGADO
----------------------------------------
O app executa apenas processos deterministicos e configurados.

Pode:
- coletar;
- pesquisar;
- testar URLs;
- materializar;
- converter formatos;
- validar requisitos tecnicos;
- aplicar circuit breaker;
- respeitar timeout;
- salvar arquivos;
- acumular candidatas em PARA_ANALISE;
- registrar metricas;
- gerar logs;
- usar configuracoes persistentes;
- continuar coleta noturna.

Nao deve:
- aprovar semanticamente imagens;
- inventar decisao visual;
- fingir QA visual;
- relinkar de forma criativa sem regra;
- criar representacao visual;
- montar imagens;
- reduzir regua de qualidade.

SUPERVISOR IA = LIGADO
----------------------------------------
O app continua executando deterministicamente, mas o MCP libera
controle supervisor completo para o ChatGPT.

O ChatGPT pode:
- ler o estado consolidado;
- ver gaps;
- ver candidatas reais materializadas;
- inspecionar visualmente imagens;
- aprovar;
- rejeitar;
- pedir relink;
- trocar referencia;
- trocar fonte;
- alterar query;
- ajustar timeout;
- bloquear/desbloquear host;
- mudar prioridade de fonte;
- cancelar uma rota;
- pausar item;
- retomar item;
- mandar continuar;
- aplicar somente correcoes tecnicas permitidas;
- salvar configuracoes que funcionaram;
- ajustar perfis de coleta;
- congelar aprovados;
- trabalhar somente nos gaps.

IMPORTANTE:
"LIGAR SUPERVISOR IA" NAO SIGNIFICA CHAMAR UMA API DE IA.

Significa:
CHATGPT VIA MCP = SUPERVISOR OPERACIONAL.

5. COLETA NOTURNA
======================================================================

Criar um modo:

MODO COLETA NOTURNA

Objetivo:
nao tentar chegar ao asset final perfeito durante a coleta.

Objetivo da noite:
MATERIALIZAR O MAXIMO DE CANDIDATAS TECNICAMENTE VALIDAS
COM CHANCE RAZOAVEL DE SERVIR.

A coleta noturna pode funcionar sem Supervisor IA ligado.

Fluxo:

conceitos
  -> configuracoes salvas
  -> fontes prioritarias
  -> queries
  -> teste de URLs
  -> materializacao
  -> validacao tecnica
  -> salvar em PARA_ANALISE

Durante a noite, o sistema NAO precisa:
- decidir semanticamente a melhor imagem;
- aprovar visualmente;
- insistir em uma candidata ruim;
- tentar "salvar" imagem errada;
- montar contexto;
- criar imagem;
- usar LLM para cada microdecisao.

Pode acumular:
- 5;
- 10;
- 20;
- ou mais candidatas por conceito,
conforme configuracao e custo.

Importante:
preview, thumbnail, pagina e link nao contam como candidata real.

Candidata real exige:
VISUAL_DISPONIVEL + MATERIALIZACAO_OK

======================================================================
6. REFINAMENTO PELA MANHA
======================================================================

Pela manha, com Supervisor IA ligado:

1. ChatGPT chama o MCP.
2. Recebe resumo da coleta.
3. Ve candidatas materializadas.
4. Faz QA visual.
5. Congela boas.
6. Rejeita ruins.
7. Relinka gaps.
8. Ajusta fontes/queries/configuracoes.
9. Salva os aprendizados operacionais.
10. Manda continuar apenas nos gaps.

Exemplo de resumo:

100 conceitos
1.840 URLs testadas
426 arquivos materializados
318 PARA_ANALISE
73 conceitos com candidatas
27 gaps
12 hosts bloqueados por circuit breaker
4 novas rotas com alta taxa de sucesso

O ChatGPT deve comecar pelo que ja existe,
e nao reiniciar a busca do zero.

8. REGRAS VISUAIS DO PIPELINE
======================================================================

REGRA ABSOLUTA:
NAO CRIAR A REPRESENTACAO VISUAL DO ROTEIRO.

Fluxo:
ROTEIRO
-> REFERENCIA CONHECIDA
-> BIBLIOTECA OU BUSCA
-> SELECAO
-> MATERIALIZACAO
-> QA

Para cada termo:
"Qual personagem, objeto, cena, local, veiculo, arma ou elemento conhecido
de anime, cartoon, game, serie, filme ou universo geek ja representa isso?"

Preferencia de nicho:
ANIME
-> CARTOON
-> GEEK
-> GAME/SERIE/FILME COMPATIVEL
-> FOTO REAL COMO ULTIMO FALLBACK

CONTEXTUAIS:
- devem vir praticamente prontos;
- personagem/objeto + acao + cenario pertencem a mesma imagem;
- nao montar contextual.

ISOLADOS:
- podem usar PNG/render pronto;
- ou imagem correta com fundo simples;
- remover SOMENTE o fundo.

Presets com transparencia obrigatoria:
- FOCO_4
- CENTRAL_2

Demais presets:
- devem ter fundo real;
- nao usar fundo chapado/solido como substituto.

======================================================================
10. REGRA DE FALHA E EFICIENCIA
======================================================================

Se uma candidata falhar:
NAO RETENTAR A MESMA IMAGEM REPETIDAMENTE.

Ordem:
1. outra fonte da mesma referencia;
2. outra candidata da mesma referencia;
3. outra referencia conhecida;
4. biblioteca madura, se aplicavel.

Depois de 2 tentativas tecnicas sem melhora clara:
REAVALIAR ANTES DE UMA TERCEIRA.

Custo afundado nao justifica continuar.

Se uma rota estiver:
- lenta;
- cara;
- repetitiva;
- fraca;
trocar de rota automaticamente ou por decisao do Supervisor.

Aprovou:
CONGELA.

Nunca reabrir aprovados porque outros falharam.

Trabalhar somente nos gaps.

13. EXEMPLOS DE PERFIS / REGRAS APRENDIDAS
======================================================================

FANDOM / WIKIA CDN
----------------------------------------
- excelente para personagens isolados;
- preferir CDN direto;
- static.wikia.nocookie.net;
- evitar depender da pagina Fandom;
- tentar filename canonico;
- aceitar PNG/WebP/JPG;
- converter quando necessario;
- timeout curto;
- apos falha materializada, trocar candidata.

YOUTUBE THUMBNAIL
----------------------------------------
- mais util para contextual;
- conferir logo/texto;
- se dois frames do mesmo video forem ruins, abandonar video;
- nao insistir em varios frames equivalentes.

ZEROCHAN
----------------------------------------
- bom para anime/cartoon;
- pode funcionar bem para contextual;
- verificar fanart, patch, montage e white background;
- medir taxa de aprovacao visual.

PINTEREST
----------------------------------------
- usar como descoberta;
- materializacao pode ser menos confiavel;
- reduzir prioridade se taxa de aprovacao/materializacao for baixa.

21. TEMPO REAL — LIMITACAO E MODELO OPERACIONAL
======================================================================

Enquanto uma execucao do ChatGPT estiver ativa:
o Supervisor pode conduzir o app em ciclo via MCP.

O MCP sozinho nao "acorda" espontaneamente uma conversa do ChatGPT.

Portanto:

COLETA NOTURNA
- roda sozinha deterministicamente.

REFINAMENTO
- comeca quando o ChatGPT entra em execucao;
- le o estado;
- assume controle;
- conduz pelo MCP.

Para iniciar automaticamente uma sessao futura,
pode existir futuramente um agendador/orquestrador.

Mas isso NAO exige Llama/Qwen dentro do app.

======================================================================
22. CIRCUIT BREAKER
======================================================================

Circuit breaker deve existir por:

- host;
- fonte;
- query;
- tipo de erro;
- opcionalmente universo/tipo.

Exemplo:

2 falhas consecutivas de materializacao no mesmo host
-> bloquear temporariamente;
-> testar proxima rota.

Erros como:
403
404
429
timeout
mime invalido
arquivo vazio
anti-hotlink
devem alimentar metricas.

Nao fazer dezenas de chamadas iguais apos erro estrutural.

======================================================================
24. MIGRACAO DO SUPERVISOR ATUAL
======================================================================

Remover o Cloudflare AI do caminho principal.

Problemas que deixam de ser relevantes no fluxo principal:

- HTTP 400 — System message must be at the beginning;
- HTTP 403 — Model Agreement;
- HTTP 429 — Neurons;
- SUPERVISOR_AI_INVALID_JSON;
- timeout de inferencia;
- provider_mode DETERMINISTIC_FALLBACK;
- licenca Llama;
- custo Workers AI.

O fallback deterministico continua existindo,
mas apenas como executor e planejador tecnico basico.

Nunca deve fingir:
- QA visual;
- aprovacao semantica;
- inteligencia que nao ocorreu.

======================================================================
25. CLOUD AI COMO FALLBACK OPCIONAL
======================================================================

Opcionalmente, manter Cloudflare AI escondido como fallback.

Somente usar se:
- usuario explicitamente desejar autonomia total sem ChatGPT;
- nenhuma sessao do Supervisor estiver ativa;
- houver necessidade real.

Nao deve ser requisito do funcionamento normal.

- toda decisao deve registrar quem/como ocorreu;
