PRINCIPIO
- Chat/MCP transporta somente JSON, IDs, status e URLs assinadas.
- THUMB entra por URL HTTPS ou upload PUT assinado direto ao R2.
- ZIP final sai por URL GET assinada do R2 para o agente local/PC.
- MCP file resource delivery permanece estruturalmente DISABLED.

THUMB — URL
1. fast_push_generated_media ou importar_midia_por_url.
2. Exige project_id, kind=THUMBNAIL, name e image_url HTTPS.
3. Backend baixa servidor->servidor, valida imagem/dimensoes, calcula SHA-256, deduplica, grava/reusa R2 e vincula ao projeto.
4. Retorna asset_id, r2_key, width, height, sha256, status e operation_id.

THUMB — UPLOAD DIRETO
1. preparar_upload_midia cria upload_token, future_r2_key e upload_url PUT assinada.
2. Agente envia bytes diretamente ao R2 com o Content-Type retornado.
3. confirmar_upload_midia valida existencia/tamanho/imagem, cataloga/vincula e retorna asset_id.
4. Token e confirmacao sao idempotentes.

THUMB — QA
- obter_thumbs_links retorna preview_signed_url, asset_id/candidate_id, contexto, dimensoes, SHA e status.
- fast_decidir_thumbs_lote aplica APPROVE / REJECT / SELECT.
- fast_push_thumb_arquivo nao existe na superficie MCP.

ZIP FINAL
1. gerar_pacote_final cria/reusa download_packages e retorna QUEUED + package_id + operation_id.
2. Data Plane reivindica atomicamente o job e processa QUEUED -> PROCESSING -> READY_FOR_DOWNLOAD.
3. O ZIP e salvo no R2; nenhum arquivo e anexado ao chat.
4. listar_pacotes_prontos_para_download retorna JSON enxuto de pacotes.
5. obter_link_download_pacote emite URL GET R2 assinada fresca + expires_at + filename + size_bytes + sha256.
6. Agente local baixa diretamente para o PC e valida SHA-256.
7. confirmar_download_pacote marca DOWNLOADED; chamadas repetidas sao idempotentes.

IDEMPOTENCIA / CONCORRENCIA
- Pacote unico por project_id + production_revision + type.
- Projeto sem alteracao reutiliza o mesmo package_id e o mesmo ZIP/hash; somente o link assinado e renovado.
- Claim de processamento usa UPDATE ... WHERE status='QUEUED'.
- Dois workers nao processam o mesmo package_id.
- PROCESSING obsoleto por mais de 10 min retorna a QUEUED para recuperacao.
- FAILED pode ser reenfileirado sem criar pacote duplicado.
- Confirmacao concorrente de download nao incrementa download_count duas vezes.
